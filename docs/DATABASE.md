# Base de datos

Motor de desarrollo: **H2 en memoria** (`jdbc:h2:mem:polizasdb`). El esquema está en
`backend/src/main/resources/schema.sql` y los datos de demostración en `data.sql`.
Hibernate está en modo `validate`: si una entidad no coincide con el esquema, la app no arranca.

## Convenciones

- Tablas en **plural** y `snake_case`: `polizas`, `siniestros`.
- Columnas en `snake_case`; en Java se mapean a `camelCase` con `@Column(name = "...")` explícito.
- Clave primaria `id BIGINT GENERATED BY DEFAULT AS IDENTITY`.
- Claves foráneas `<entidad_singular>_id` (`cliente_id`, `poliza_id`) con constraint `fk_<tabla>_<referencia>`.
- Índices `ix_<tabla>_<columna>`; checks `ck_<tabla>_<columna>`.
- Enums guardados como `VARCHAR` con el nombre del enum (`@Enumerated(EnumType.STRING)`) y un `CHECK` con los valores permitidos.
- Montos `DECIMAL(p, 2)` en USD; en Java `BigDecimal`. Nunca `double`.
- Fechas de negocio `DATE` (sin hora); en Java `LocalDate`.
- Los `INSERT` de `data.sql` no especifican `id` (para no desincronizar la identidad) y usan fechas relativas a `CURRENT_DATE`.

## Tablas

### `clientes`

| Columna | Tipo | Nulo | Descripción |
|---------|------|------|-------------|
| `id` | BIGINT | no | PK |
| `nombre_completo` | VARCHAR(150) | no | |
| `documento_identidad` | VARCHAR(20) | no | Único. Formato `V-########` / `E-########` (ficticio) |
| `email` | VARCHAR(150) | no | |
| `telefono` | VARCHAR(30) | sí | |
| `fecha_nacimiento` | DATE | no | Usada para reglas de edad en VIDA |
| `fecha_registro` | DATE | no | Dato interno, no se expone en la API |

### `polizas`

| Columna | Tipo | Nulo | Descripción |
|---------|------|------|-------------|
| `id` | BIGINT | no | PK |
| `numero` | VARCHAR(20) | no | Único. Formato `POL-<TIP>-<nnnn>` (p. ej. `POL-AUT-0001`) |
| `cliente_id` | BIGINT | no | FK → `clientes.id` |
| `tipo` | VARCHAR(10) | no | Enum `TipoPoliza` |
| `estado` | VARCHAR(15) | no | Enum `EstadoPoliza` |
| `suma_asegurada` | DECIMAL(14,2) | no | Monto máximo cubierto |
| `prima_anual` | DECIMAL(12,2) | no | Calculada al emitir (ver REGLAS_NEGOCIO.md) |
| `fecha_inicio` | DATE | no | Inicio de vigencia (inclusive) |
| `fecha_fin` | DATE | no | Fin de vigencia (inclusive) = `fecha_inicio + 1 año` |
| `motivo_cancelacion` | VARCHAR(255) | sí | Solo si `estado = CANCELADA` |

### `siniestros`

| Columna | Tipo | Nulo | Descripción |
|---------|------|------|-------------|
| `id` | BIGINT | no | PK |
| `poliza_id` | BIGINT | no | FK → `polizas.id` |
| `fecha_ocurrencia` | DATE | no | Debe estar dentro de la vigencia de la póliza |
| `fecha_reporte` | DATE | no | Fecha de registro en el sistema |
| `descripcion` | VARCHAR(500) | no | |
| `monto_reclamado` | DECIMAL(14,2) | no | `> 0` y `<= polizas.suma_asegurada` |
| `estado` | VARCHAR(15) | no | Enum `EstadoSiniestro` |

## Enums

| Enum | Columna | Valores |
|------|---------|---------|
| `TipoPoliza` | `polizas.tipo` | `AUTO`, `HOGAR`, `VIDA` |
| `EstadoPoliza` | `polizas.estado` | `VIGENTE`, `VENCIDA`, `CANCELADA` |
| `EstadoSiniestro` | `siniestros.estado` | `REPORTADO`, `EN_REVISION`, `APROBADO`, `RECHAZADO` |

Agregar un valor a un enum exige actualizar **los tres lugares**: el enum Java, el `CHECK` en
`schema.sql` y esta tabla.

## Reglas de datos

- Una póliza pertenece a exactamente un cliente; un cliente puede tener varias pólizas.
- Las pólizas no se borran: se cancelan o vencen. Los siniestros tampoco se borran.
- `fecha_fin >= fecha_inicio`.
- El paso de `VIGENTE` a `VENCIDA` lo hace un proceso nocturno externo (fuera de este repo);
  la app nunca recalcula el estado a partir de las fechas.
